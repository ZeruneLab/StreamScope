# StreamScope 业务插件规范（草案，Host API 1.2）

> 当前仓库版本仍是 v0.1.x，默认构建保留兼容功能。独立核心构建已关闭旧分析依赖、固定命令和随包执行器，并通过安装包解包核验；七项业务功能仍处于插件试运行/等价回归阶段。完成回归和发布验收之前不得以正式 v0.2.0 核心版发布。构建方法见 `docs/core-host-build.md`。

## 1. 包与信任

`.ssp` 是 ZIP，根目录恰好包含 `manifest.json`、`publisher.pub`、`signature.ed25519` 和清单 `files` 中的文件。清单是 UTF-8 JSON，字段以 `schemas/plugin-manifest.schema.json` 为准。`publisher.pub` 为 32 字节 Ed25519 公钥的 Base64；`signature.ed25519` 为对**原始 manifest.json 字节**签名所得 64 字节签名的 Base64。`publisher.keyFingerprint` 是 `sha256:` 加公钥原始字节的十六进制 SHA-256。`files` 每项是 `sha256:` 加包内文件原始字节的 SHA-256。清单不能把自身、签名或公钥列入 `files`。

`kind` 默认为 `feature`；共享依赖包使用 `runtime`，不得声明功能入口，只提供签名清单中的运行时文件。当前 FFmpeg 模板位于 `examples/plugin-ffmpeg`；媒体插件已声明该依赖，宿主会校验并向插件传入运行时目录。正式包尚未签名发布；本地临时密钥打包和目录校验已通过。

宿主验证签名、每个文件摘要、路径安全、大小限制（压缩包 1 GiB、展开 2 GiB、1000 项）、平台入口、宿主 API 范围和已安装依赖。Windows 路径大小写冲突、设备名、绝对路径、`..`、符号链接均拒绝。预览与确认绑定完整包 SHA-256 和公钥指纹；确认后重新验证。换签名密钥要卸载旧插件后重新确认。安装目录为当前用户 `%LOCALAPPDATA%/StreamScope/plugins`；不要求管理员权限。升级不修改报告。

第三方原生 EXE 会以当前用户身份运行，**没有系统级沙箱**。宿主 API 权限声明不能阻止插件自行打开网络或文件。安装时必须展示发布者、公钥指纹、权限及风险，由用户明确同意；签名只证明来源和完整性。不要从不信任的来源导入插件。

## 2. 进程协议

插件独立进程的 stdin/stdout 是 UTF-8 JSON 帧：4 字节 little-endian 长度，后接 JSON，单帧最大 4 MiB。stdout 不得写日志；日志输出到 stderr。请求：`{"jsonrpc":"2.0","id":1,"method":"hello","params":{"hostApi":"1.2.0"}}`，随后 `execute`（`action`、`input`）、可选 `cancel`（`taskId`）。响应的 `id` 必须匹配，`method` 取 `progress`、`result` 或 `error`，`params` 为结构化数据。握手 5 秒，当前桌面命令单次执行上限 600 秒；崩溃或超时只影响该插件任务。Windows 宿主为每个插件进程建立独立 Job，取消、超时及宿主释放进程时会终止其子进程；其他平台目前只终止插件进程。进度可显示在界面；插件内协作式取消尚未完成；该执行模型不适用于数小时抓包。

Host API 1.1 新增 `select` 输入、语法树及文件另存组件；仍兼容声明 `^1.0` 的原有包。需要新增组件的插件应声明 `^1.1`，避免旧宿主安装后无法提供界面。进程协议握手返回的 `pluginApi: "1.0.0"` 是协议版本，不等同于宿主功能 API 版本。

Host API 1.2 增加报告联动动作 `actions` 与宿主产物交接；仍满足已安装包的 `^1.0` / `^1.1` 范围。使用联动动作的新插件须声明 `^1.2`，不能把未知组件在旧宿主上可显示视为兼容。

大 PCAP、码流、预览不通过 JSON 逐包传送。文件选择输入会由核心流式复制到报告根目录下的 `.artifacts`，SHA-256 去重、标记只读并在交付插件前复核；复制进度在桌面与 CLI 显示，桌面取消可中断复制，插件收到文件路径及 `_hostArtifacts` 字段 ID。核心只接受当前任务报告目录内的预览文件，复制为受校验产物后才能由宿主媒体组件播放。原生进程仍可凭 Windows 当前用户权限操作文件，故“只读”不是系统级沙箱；未引用产物清理还需补齐。

## 3. 界面与报告

`ui.kind` 必须为 `declarative`，不得包含第三方 HTML/JS。入口由已启用插件的 `contributions` 动态提供。输入白名单实现纯文本、文字/密码/数字/文件/复选输入及 `select`（`id`、`label`、字符串数组 `options`、布尔值 `required`）。结果块由宿主渲染 `text`、`table`、`series`（`points: [{x,y}]`）、`timeline`（`events: [{offsetMs,label,detail?}]`）、`hex`（`bytesHex`、可选 `fields`、绝对 `byteOffset`、`truncated`）、`syntaxTree`（`nodes: [{label,value?,byteOffset?,children?}]`）、`media`（核心产物 ID 和音/视频类型）、`download`（`artifactId`、`filename`）、`frameOverlay`（帧宽高、QP 矩形、运动矢量坐标和可选 `frameArtifactId`）及 `report`（受宿主路径检查的本地 HTML 报告）。语法树可折叠，最多渲染 2,000 节点、17 层；HEX 可选字号，最多显示 4,096 字节；结构化结果仍保留在原始 JSON 中。超出解析器 HEX 限量的原始字节保留在输入产物，而不是完整写入 JSON。未通过白名单的输入类型被拒绝，未知结果块仅保留在原始 JSON 中。

H.264/H.265 官方插件另有 `inspect-nalus` 动作：输入裸 Annex B 文件、`firstNalu`/`lastNalu`（从 1 开始，最多 50 个，总保留数据 8 MiB），使用共享流式读取器和原有解析器返回已确认字段、文件偏移及 HEX。支持头部、参数集与现有 Slice 前缀；不把这一入口宣称为完整 Slice 语法解码、帧映射或 RTP 关联。

`frameOverlay` 的帧图像必须由宿主从本次报告目录导入、校验 SHA-256 后绑定产物 ID；没有帧图像时仍显示空间分布。文件选择控件必须声明 `file-read`，宿主报告目录只传给声明 `report-write` 的插件。插件可返回任务报告目录内的 `downloadFile`；核心将其导入内容寻址产物并生成 `download` 组件。保存时重新验证摘要，再经原生保存对话框选择目标；不允许覆盖核心报告或已安装插件目录。媒体预览提供明确的另存按钮，不依赖浏览器原生下载菜单。音频插件的导出入口可选 WAV/MP3/M4A/FLAC/Ogg 及可选毫秒区间；不会改写原始文件。

CLI 可用 `streamscope plugin list` 列出当前用户的已安装功能及动作；`streamscope plugin run --id <插件 ID> --action <动作> --input <JSON 文件> --output <报告目录>` 使用相同注册表执行插件并保存 v2 报告。输入使用文件而不是命令行 JSON，以免凭据直接出现在进程参数里。核心 CLI 构建关闭 `compat`，仅注册插件命令；兼容版继续保留旧命令。核心 CLI 的签名示例包安装、执行、产物保存及禁用拒绝已通过临时用户目录测试。

已建立独立的 v2 JSON 容器：宿主保存摘要、命名空间化且带版本的插件结果，以及证据、时间线和实际内容寻址产物引用。插件结果中的 `evidence` 和 `timeline` 会脱敏、限量后写入核心字段；SIP 和媒体插件已提供这两类数据。卸载插件后管理页仍能读取容器；旧 `AnalysisResult` 报告路径保持原样、只读查看；所有既有功能的迁移尚未完成。

## 4. 官方发布与兼容

官方目录必须独立于主程序 GitHub `releases/latest`，目录本身签名并含每个 `.ssp` 的 URL、SHA-256、发布者指纹、版本和兼容范围。目录可以同时包含多平台或未来 API 版本；验签后筛选兼容项，不因单个不兼容项拒绝整个目录。依赖优先复用满足版本范围的已安装包，否则选择符合 SemVer 范围的最高兼容版本（默认范围不会隐式选择预发布版）。下载包的 API 范围、身份与签名目录必须一致。

安装前解析最多 100 项多层依赖，检测循环、共享依赖版本冲突，再一次展示所有安装/启用动作、发布者指纹、权限与风险；确认后按依赖顺序执行。冲突时停止并提示，不擅自改变版本约束；每个包独立原子安装，若后续失败，已成功安装的依赖保留，尚未安装的下载临时包清理。升级依赖不得破坏其他已安装插件的版本约束（包括禁用插件）。正式发布公钥与目录地址尚未配置，因此当前构建只能离线导入，线上一键安装未验收。配置与发布流程见 `docs/plugin-catalog.md`。第三方首版只支持手动导入；默认兼容版仍随包 FFmpeg，核心预览版不随包。

正式 v0.2.0 验收前必须逐项对照旧版样本：ONVIF、SIP、音频、H.264、H.265、深度视频、RTSP、PCAP；检验核心空安装、旧报告只读、按用户安装、离线导入、独立更新、崩溃/超时/依赖循环/回滚，且主程序更新不受插件目录发布影响。

## 5. 报告与插件联动（Host API 1.2）

插件化不得把同源媒体联合分析变成互不相关的文件输入页。当前桌面提供 PCAP 扫描 → 指定流重组/解码 → 原始视频逐帧 QP/运动矢量、NALU 语法/HEX；指定音频流 → 解码 WAV → 音频质量与格式/区间导出。RTSP 和 H.264/H.265 文件结果也提供同源深度入口。视频深度入口传递重组的原始 Annex B 码流，不使用 PCAP 或转码预览替代。

结果块格式：`{"type":"actions","title":"stream-0001 · h264","actions":[{"id":"stream-0001-frame","title":"视频深度分析","pluginId":"org.streamscope.video-deep"}]}`。实际动作定义保存在同份 v2 结果的 `hostActions` 数组，每项包含 `id`、`title`、`pluginId`、目标 `action`、字符串默认参数 `input`、文件字段到报告产物 ID 的 `artifactInputs` 和 `context`。例如 `artifactInputs: {"path":"sha256:…"}`。产物必须已列入来源报告 `artifacts`；不得把第三方路径当成可信产物引用。目标插件仍须安装、启用并声明该动作及文件输入。

桌面先调用 `prepare_plugin_continuation`（参数 `reference: {reportId,actionId}`）从保存的来源报告取目标和产物，检查插件、字段及摘要；只填充参数，不自动执行或发送网络请求。用户执行时，`execute_plugin` 接收同一 `continuation` 引用，再次核验目标和摘要；文件输入以来源产物替换，不信任前端提交的路径。新报告的 `workflowSource` 保存来源报告编号、动作编号和流上下文。没有目标插件时提示安装/启用，原报告仍保留。选择新文件会解除此前产物关联。

已安装迁移插件的旧 `result.json` 由宿主适配器**只读取协商好的报告元数据**（流目录、编码和预览路径），不在核心重新解析 RTP/媒体、不引入私有分析 crate。采用缓冲流式反序列化跳过 RTP/NALU 明细，报告上限 512 MiB；文件仍须位于任务报告目录内。旧 v2 报告在查看时可补充联动，不改写原始 JSON/HTML；样本已被移走时只给出联动不可用提示。PCAP 输入被误送至视频/音频插件时，在宿主阶段给出选流指引，不再只返回 FFmpeg 无效输入错误。

桌面导航仅缓存当前会话中的参数/结果；切换页面不丢失结果，提供返回来源及上一份分析结果。密码输入在执行后或离开页面时清空，不写入页面缓存快照。多流联动入口可按流 ID、编码和地址搜索，当前一次展示前 100 个匹配项，不把全部流混为一份媒体样本。CLI 尚未提供桌面的联动导航命令；不得据此宣称所有旧页面操作已经等价迁移。
