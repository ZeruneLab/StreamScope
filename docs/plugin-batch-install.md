# 插件批量下载安装与管理界面

## 使用方式

1. 在插件管理页检查官方目录。
2. 勾选需要的插件，或使用“全选可安装项”，点击“批量下载安装”。单项下载安装仍然保留。
3. 等待下载、签名/哈希校验和依赖预检完成。
4. 核对统一确认区中的发布者、公钥指纹、包摘要和权限，勾选信任后确认安装。

目录显示中文名称、用途、远端版本、本机版本和状态。签名详情仍可在已安装插件卡片中展开查看。

## 执行与安全边界

- 多个所选插件使用同一依赖时只解析、安装一次；直接选中的依赖也纳入同一安装图。
- 所有依赖预检通过后才申请统一确认；版本冲突、循环依赖导致本批次不执行安装。
- 下载或包校验失败会记录在对应项目中，其他独立项目仍可继续准备。
- 安装按依赖顺序串行执行；依赖安装失败时跳过其下游，其他独立项目继续。
- 已成功安装的项目保留；失败和跳过项目可重新勾选重试。不是整批事务回滚。
- 取消确认或在确认前离开页面不安装，并清理已准备的下载包。
- 每项显示等待、下载并校验、待确认、安装、完成或失败原因；总体进度按处理项目计数，不代表下载字节百分比。
- 官方包解压和安装校验放在后台线程，保留原有状态锁、空闲检查、原子切换和单包回滚逻辑。
- 不改发布者密钥迁移策略，不绕过签名、哈希、权限确认或依赖检查。密钥变化仍然拦截。
- 原生插件没有系统级沙箱；确认区明确展示此风险。

- `npm run build:core`：TypeScript 检查和核心前端构建。
- `node scripts/verify-plugin-components.mjs`：单项/批量依赖图、共享依赖、已选依赖、循环及版本冲突。
- `node scripts/verify-plugin-ui-layout.mjs`：隔离无头浏览器、模拟 IPC，验证多选/全选、统一信任确认、取消/离开清理、依赖失败隔离、失败重试、运行时复用、单项安装及密钥变更拦截；同时回归原有 PCAP 联合分析页面。检查 1280 / 1000 像素宽度布局。

- `cargo test -p streamscope-plugin-host --offline`：已有签名/哈希、路径、依赖、回滚及报告测试。
