# StreamScope 音频分析与音画同步实施方案

日期：2026-09-14  
状态：分阶段实施中。已完成多轨 RTSP 接收、纯音频 RTSP/抓包、常见音频文件导入、PCMA/PCMU PCM 分析、AAC-hbr/Opus 样本试听与解码质量扫描、RTCP SR/CNAME 时钟映射、离线音画配对报告和基础音频诊断；采集中共享时钟同步播放、内容事件同步、完整 RR 指标等仍按本文后续阶段推进。

## 1. 最终目标与范围

将 StreamScope 扩展为支持多路音视频的诊断工具，实时和离线使用同一套分流、解码、时间映射及诊断逻辑。

最终交付包含四项能力：

1. 纯音频可以独立采集、分析、试听、生成报告，不依赖视频轨存在。
2. 音视频共存时，每轨独立分析，并可选择相关音视频轨进行同步播放和同步诊断。
3. 实时任务在采集过程中显示视频、播放声音和更新指标；结束后仍可回放保留样本。
4. 离线抓包、音频文件、音视频容器和有时间依据的分离文件都能分析；证据不足时清楚说明哪些指标无法计算。

“音画同步”同时包含：按已有时序正确播放、检查时序一致性，以及通过校准信号验证实际声画对应关系。不能仅凭 RTP/PTS 合法，就判定人的口型和声音一定同步。

| 输入场景 | 音频独立分析 | 视频分析 | 同步分析与播放 |
| --- | --- | --- | --- |
| 实时 RTSP，纯音频 | 支持 | 不适用 | 独立试听、音频时钟和连续性 |
| 实时 RTSP，音视频多轨 | 支持 | H.264/H.265 | 同会话采集、轨道配对、同步播放与诊断 |
| 实时 RTP/UDP + SDP | 支持 | 已支持的 RTP 视频编码 | 根据 SDP、RTCP 和来源信息判断可同步性 |
| PCAP/PCAPNG | 每流支持 | 每流支持 | 选择音视频组合深度分析，同步关系可确认或手动指定 |
| WAV、FLAC、AAC/ADTS、MP3、Ogg/Opus 等文件 | 支持，依赖解码器能力 | 不适用 | 独立试听和音频时间线 |
| MP4、MKV、MPEG-TS 等容器 | 支持 | 已支持的视频编码 | 保留容器时间轴并联合分析 |
| H.264/H.265 裸流、原始 PCM/G.711 | 支持适用部分 | 支持 | 原始同步信息缺失时，需额外时间索引或人工对齐 |

裸 PCM/G.711 导入需指定编码、采样率、声道数，以及必要的字节序。裸 H.264/H.265 与独立音频文件不能仅凭文件创建时间恢复原始同步。

RTSPS、SRTP 解密、WebRTC 协商、ONVIF、主观 MOS 评分与任意场景自动唇读同步，不作为本轮完成条件。识别到不支持的输入时显示明确原因。

## 2. 现有基础与必须改造的部分

代码检查结论：

- `crates/rtsp/src/client.rs` 通过 `find_video_track` 选择单条视频轨，目前不能完成纯音频或同会话多轨接收。
- `crates/capture` 已支持多流分组、TCP 重组和每流证据索引，可复用；未知编码的时钟默认值及视频推断逻辑需要审查，不能套用于音频。
- `crates/rtp` 已能识别部分 RTCP 包，但 SR 只保留 SSRC/RTP 时间戳，SDES 只保留数量，缺少 NTP、CNAME 和完整接收报告。
- 当前解码使用 `0:v:0` 并禁用音频；当前画面是分析后的样本回放，尚非采集中的连续播放。
- 现有裸流重组样本可以用于解码，但会丢失原始封装时序。音画同步必须使用原始时间索引，不能以重新探测的帧率重建全部时间。
- 上一次设备短时实测记录 `rtcp_packet_count = 0`。这只说明该次窗口未记录到 RTCP，不能证明设备永远不发送，也不能据此证明音画同步。

优先改造数据源与时钟，再做音频质量和同步评分，避免后期重做。

## 3. 数据模型与模块分工

保留现有逐流证据体系，引入以下最小必要对象：

| 对象 | 必需信息 |
| --- | --- |
| MediaTrack | 轨道 ID、媒体类型、编码、PT 映射、RTP 时钟、音频采样率/声道、控制 URI、流分组键、采集阶段 |
| PacketEvidence | 原包号/包序、到达或抓包时间、SSRC、扩展序列号、扩展 RTP 时间戳、负载范围 |
| MediaUnit | 音频访问单元或视频帧 ID、关联 RTP 包、原始时间戳、PTS/DTS、持续时间、完整性、解码状态 |
| ClockMapping | SR 的 NTP/RTP 对、来源和阶段、时间基准类型、拟合参数、覆盖区间、残差和可靠性 |
| AudioAnalysis | 声道参数、包时长、解码采样数、音频异常区间、实际分析覆盖、限制说明 |
| SyncGroup | 音视频轨组合、关联证据、自动或手动配对、有效区间 |
| SyncAnalysis | 对时状态、漂移、播放偏差、人工/校准事件偏差、测量方法与误差范围 |

时间值使用整数刻度和有理数 time base，避免长时间浮点累计误差。抓包到达时间、媒体采样时间、解码完成时间和播放时间分别保存。

新增 `crates/audio` 负责音频负载与分析，新增 `crates/sync` 负责轨道配对和时钟映射。现有 RTP、RTSP、抓包、FFmpeg、报告和桌面模块做定点扩展；实时与离线共享上述两个核心模块。

结果 schema 升级并兼容旧报告。旧报告缺失的音频/同步信息显示“未采集”，不填零，也不自动升级为正常。

## 4. 音频编码和独立分析

### 4.1 编码顺序

| 顺序 | 支持范围 | 重点 |
| --- | --- | --- |
| 第一批 | G.711 PCMA/PCMU | 静态 PT 在匹配 RTP profile 时使用；动态 PT 依赖 SDP；按采样数计算包时长 |
| 第一批 | AAC-LC，MPEG4-GENERIC 常见 AAC-hbr | 解析 fmtp/config 和 AU Header；处理一包多 AU、分片和缺片；不把任意 RTP 负载直接当 ADTS |
| 第二批 | Opus | RTP 时钟固定 48 kHz；解析可变包时长；区分 DTX、丢包和解码补偿 |
| 第三批 | AAC 的 MP4A-LATM 常用模式 | 独立适配 LATM，明确支持的配置；不能与 MPEG4-GENERIC 混解 |

每种编码同时验收实时接收、离线抓包和试听。文件解码支持范围与 RTP 负载支持范围分别展示：FFmpeg 能打开某个音频文件，不代表软件已经会解包该编码的 RTP。

### 4.2 音频指标

- RTP：包数、序列缺口、迟到、乱序、重复、码率、抖动和到达间隔。
- 时序：RTP 时间戳步长、访问单元持续时间、连续性、时间戳重置和时钟漂移。
- 解码：输出采样数、实际音频时长、声道数、采样率、错误位置和缺失区间。
- 画面对应的音频界面：波形、分声道电平、峰值、RMS、可选频谱和异常标记。
- 听感候选：持续静音、异常中断、削波、突变/疑似爆音、重复片段。

音频 RTP Marker 按编码语义处理，不能沿用视频的帧结束判断。估计丢失音频时长时，必须区分固定包时长、可变包时长、DTX 和舒适噪声；信息不足时输出范围或未知。

真实静音、设备静音、链路无包、解码失败和播放设备无声分别呈现。PLC/FEC 恢复、填充静音、丢帧等行为要记录，不能隐藏后仍报告原始数据完整。

## 5. 实时与离线处理链路

### 5.1 实时

同一次 RTSP 会话执行 DESCRIBE → 发现轨道 → 按选择对各轨 SETUP → PLAY → 并行接收音频、视频及 RTCP。仅存在音频时也能完整执行。

TCP 使用统一读取器分发各 Interleaved Channel；UDP 使用各轨协商端口。保留 Session、Transport、RTP-Info 和各轨错误，不假定设备始终使用固定通道号或支持全部轨道。

接收到的同一批数据同时进入：

1. 原始证据记录及时间索引。
2. 逐轨统计、重组与异常分析。
3. 有界播放缓冲、解码和软件内播放器。

不得为预览偷偷另开一条 RTSP 拉流。单轨失败时其他可用轨继续，整体报告标记部分成功。采集、解码与 UI 线程隔离；播放拥塞不能阻塞采集，任何主动丢弃都计数并区分原因。

提供“开始/停止、音频轨、视频轨、静音/音量、当前延迟、播放状态”。停止时结束会话、回收后台进程、落盘报告。可设置采样时长，也可持续运行直至手动停止。

### 5.2 离线

抓包先扫描，列表同时显示音频、视频及未知流。用户可以独立深度分析音频，也可以选择一个同步组联合分析。多路默认分组展示，不能把所有音频与所有视频逐个组合。

没有 SDP 的动态音频编码允许导入配套 SDP，或人工指定 PT、时钟、声道及 fmtp。保存人工选择及适用范围，并标明“人工指定”。未知负载仍可统计包和字节，无法确定时钟时不显示伪造的毫秒抖动。

容器文件使用原始 PTS/DTS/time base，处理非零起点、负时间、轨道偏移、编辑列表及编码预延迟。离线分析结束提供试听/同步回放、拖动定位和异常跳转。

## 6. 音画同步：从时间基准到实际播放

### 6.1 先关联，再对时

关联综合使用 RTSP 会话、SDP 控制信息、RTCP CNAME、协商端口/通道和流生命周期。相同 IP、SSRC 或首包相近都不能单独证明音视频属于一组。

一个设备可能有多条视频轨和多条音频轨，同一音频也可能供多个视频预览使用。软件只对有依据的组合自动建组；歧义组合交由用户选择，手工选组不等于已经获得时间基准。

### 6.2 建立共同时间轴

有可靠 SR 时，可用参考点换算媒体采样时间：

```text
媒体参考时间 = SR.NTP + (扩展 RTP 时间戳 - SR 扩展 RTP 时间戳) / RTP 时钟频率
```

该映射需要验证音视频发送端采用可比较的参考时钟，并处理时间戳回绕、SSRC 重启、时钟变化、异常 SR 和 NTP 跳变。长时间分析用多个 SR 检查频率误差和映射稳定性；单个 SR 只能给局部参考，不能可靠估计长期漂移。

SR 提供的是媒体时间关系，不直接给出“口型落后声音多少毫秒”。仅比较音视频首包，或任选一张视频帧与一个音频包相减，都不能当成真实同步误差。依据见 RFC 3550 [1]。

### 6.3 同步能力分级

| 状态 | 可提供的结果 | 不应输出的结论 |
| --- | --- | --- |
| 共同时间基准有效 | 媒体时间映射、连续性、相对漂移及播放调度偏差 | 未校准的真实口型误差 |
| 容器时间轴有效 | 文件内原始时序、轨道偏移及同步回放 | 未经验证的拍摄端时钟准确性 |
| RTSP RTP-Info/Range 等可建立映射 | 经完整性检查后的会话时间轴和同步回放 | 把单条响应当永久时钟证明 |
| 只有同一抓包点到达时间 | 到达偏差、缓冲需求及估算播放 | 精确发送端或内容同步误差 |
| 只有独立裸文件 | 人工对齐回放、各自质量分析 | 自动恢复原始音画起点 |
| 只有音频或只有视频 | 单轨分析和播放 | 音画同步评分；显示“不适用” |

RTCP 缺失时提示延长观察或导入更多证据；不会无期限等待。允许估算或人工校准，但报告必须保留方法和限制。

### 6.4 同步播放实现

播放系统按共同时间轴调度。存在音频时以音频实际播放位置为主时钟，视频依 PTS 展示；纯视频用单调时钟。监测音频缓冲、视频迟到、欠载、丢帧和暂停状态。

先做播放器技术验证：优先使用保留原始时序的单个音视频播放管线。H.265 需兼容转换时，转码不得重置音视频各自起点或改变原始相对偏移。裸流解码后的帧率估值不能替代原时间索引。

独立 `<audio>` 与 `<video>` 同时调用播放不能作为同步实现；两个元素可以独立漂移。若 Tauri/WebView 管线达不到调度和时间观测要求，再引入后台解码/原生输出模块，并先用校准夹具验收。

保留两类模式：

- 证据回放：忠实保留已知时间间隔、缺失和异常；播放器必要补偿均有记录。
- 手动补偿预览：用户调节音频偏移观察效果，另存补偿参数；不会覆盖原始证据或将补偿后的偏差写成原始测量。

长期漂移补偿可做小幅重采样/视频调度，但必须在报告中区分原始漂移与播放器补偿。正常时间轴同步播放是正式验收项，自动修复所有设备错误时钟不作保证。

### 6.5 验证内容同步和物理输出

准备同一参考时钟生成的“闪光 + 短脉冲声音”测试源，包含已知偏移和已知漂移。分析闪光帧及声脉冲的位置，可测内容事件对应关系，并检查符号与时长变化。

规定 `Δ = 声音事件时间 - 图像事件时间`：正值表示声音晚，负值表示声音早。视频精度受帧间隔约束，25 fps 不能承诺任意画面都可获得 1 ms 的内容定位。

普通办公室、静态画面和连续背景声可能没有可匹配事件，应提示无法从内容自动确认。可通过播放器人工标记同一事件进行复核。

软件内部播放时钟只能证明调度情况。要验证显示器出光与扬声器出声的真实差值，需外部录制或光电/音频环回测量，单独保存设备链路延迟和测量误差。

## 7. UI 与报告

界面按任务 → 会话/同步组 → 媒体轨展示。实时和离线复用“总览、播放、RTP/RTCP、音频、视频、音画同步、异常时间线、报告”视图；纯音频隐藏不适用的视频内容。

同步页面显示：关联依据、时间基准状态、有效覆盖、时钟漂移曲线、播放偏差、校准事件偏差，以及未知项的具体原因。用户可从异常点跳转到相应音频波形和视频位置。

每条结论包含现象、证据、影响、建议和验证方法。不能以“解码成功”代替质量正常，也不能将无视频、静音或缺失 RTCP直接记为音画不同步。

报告分别显示采集覆盖时长、有效重组时长、解码时长、音频质量扫描覆盖、视频扫描覆盖及同步有效区间。音频缺失率按时间和包数分别计算，明确分母。

保存原始时间索引、逐轨样本、RTCP 对时记录、候选异常片段和播放产物。试听默认静音，由用户开启。导出时可仅导出脱敏文字报告，媒体文件需明确勾选；文本脱敏不会自动消除录音和画面中的隐私。

| 阶段 | 内容 | 可交付成果与验收 | 估算 |
| --- | --- | --- | --- |
| P0 数据可信基础 | 多媒体轨模型、纯音频任务、RTSP 多轨接收、完整 SR/RR/SDES、原始时间索引 | TCP/UDP 同时收音视频；纯音频成功；SSRC/PT/时钟变化可追踪；旧报告可读；现有视频回归通过 | 5–7 人日 |

| P2 声音质量与编码扩展 | Opus、常用 LATM、静音/中断/削波/突变、DTX/PLC 标记 | 人工注入的丢包和削波可定位；正常静音及可变包时长不被误报为网络丢包 | 4–6 人日 |

| P5 长稳和实机验收 | 多路资源约束、长时测试、校准事件/外部测量、异常片段、报告整理 | 通过下述矩阵；完成实机问题复核；软件可安装使用并明确能力边界 | 4–7 人日 |

在 P0/P1 期间先做播放器最小技术验证，及早发现 WebView、H.265、音频输出时钟或长时缓冲限制。每阶段保留可运行版本；最终完成必须包括 P4/P5，不能把离线回放当作实时同步播放交付。

## 9. 验证矩阵与完成标准

### 9.1 确定性夹具

- 编码：PCMA、PCMU、AAC-hbr、Opus、受支持 LATM；视频 H.264/H.265；多采样率、单/双声道。
- 输入：纯音频 RTSP、音视频 RTSP、独立 RTP+SDP、TCP Interleaved、UDP、PCAP/PCAPNG、容器和裸文件。
- 故障：丢包、乱序、重复、缺分片、变长包、静音、DTX、解码失败、时钟跳变、SSRC 重启、PT/编码切换。
- 同步：0、±40、±100、±300 ms 已知事件偏移；±50、±100、±500 ppm 已知漂移；初始偏移正常但逐渐失步。
- 不充分证据：无 RTCP、单个 SR、错误 SR、不同源时钟、无 SDP、无法配组、独立无时序文件。
- 容器/解码：B 帧重排、AAC/Opus 预延迟、非零起点、断续时间轴、采样缺失和预览转码。

确定性时钟夹具的映射误差目标不超过 1 ms（输入精度允许时）；漂移夹具在至少 10 分钟、多参考点且时钟稳定条件下估计误差目标不超过 10 ppm。内容事件测量按音频定位误差与视频帧间隔报告，不套用 1 ms 指标。

### 9.2 播放与长稳

- 在声明硬件配置及参考时钟有效条件下，正常同步源连续播放 30 分钟，软件可观测播放调度偏差目标 P95 ≤ 40 ms，且不持续累积；物理输出延迟另测。
- 单组音视频及纯音频分别运行 8 小时；内存进入稳定区间，队列有界，采集和停止正常，时钟回绕不产生虚假大偏差。
- 10/50/100 路抓包统计验证分组隔离；深度解码采用有限并发和队列，统计路数不等于同时播放路数。
- 实时默认一个活动预览同步组，多轨统计继续；切换预览、隐藏窗口、暂停试听不会改变原始采集计数。
- 限额触发时明确说明哪些证据停止保留，已有统计继续或明确结束任务；不让播放预览挤占唯一证据。

### 9.3 最终交付检查

1. 没有视频的实时流、抓包或文件，均能完成音频分析和试听。
2. 实时任务采集中即可播放音视频并更新质量指标；离线可选流、选组和定位回放。
3. 可靠时序下实现同步播放，能够区分初始偏移、时钟漂移、传输迟到和播放缓冲异常。
4. 缺少时间基准时提供估算/人工校准入口，报告不输出无依据的精确同步结论。
5. 可用校准源验证内容事件偏差，并保留物理输出验证方法。
6. 所有发现能追溯到包、音频 AU/采样区间或视频帧；不会把抽样序号当原始帧号。
7. 交付安装包、兼容旧报告的新报告模型、测试夹具、性能记录和已知限制说明。
